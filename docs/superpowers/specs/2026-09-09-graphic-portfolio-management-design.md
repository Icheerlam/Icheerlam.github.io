# Graphic 作品在线管理功能设计

## 目标

为 `pages/graphic.html` 增加作品管理能力，使站点所有者可以在页面内上传、删除并调整作品顺序。功能覆盖 `Graphic Design`、`AI Store Design` 和 `3D Modeling` 三个区域，同时支持图片与视频。

第一阶段完成本地管理界面和交互验证，不修改线上仓库。第二阶段接入 GitHub 身份验证与安全的服务端保存能力，使修改可以提交到 GitHub 仓库并由 GitHub Pages 发布。

## 范围

### 包含

- 页面右上角显示“管理作品”入口。
- 三个作品区域均可上传、删除和排序。
- 支持 JPG、JPEG、PNG、WebP、GIF、WebM 和 MP4。
- 上传时选择作品所属区域。
- 作品中英文标题均为可选项；标题为空时不显示标题占位。
- 桌面端支持拖拽排序。
- 移动端使用上移、下移控制，避免与页面滚动冲突。
- 管理状态支持保存、取消、删除确认和保存前撤销。
- 在线阶段通过 GitHub 登录验证管理者身份，并通过受保护的云函数提交仓库变更。

### 不包含

- 第一阶段不真正写入或删除本地项目文件。
- 第一版在线功能不物理删除仓库中的旧媒体文件，只从作品清单中移除引用。
- 不实现多管理员、角色权限或作品审批流程。
- 不改造其他作品页面。

## 页面体验

### 浏览模式

- 保持当前视觉风格、瀑布流、3D 网格、灯箱、视频播放、音效、主题切换和中英文切换。
- 页面右上角显示“管理作品”按钮。
- 不显示删除按钮、拖拽手柄、移动按钮等编辑控件。
- 在线阶段，访客点击“管理作品”后进入 GitHub 登录；非授权账号登录后显示无权限提示，不能进入管理状态。

### 管理模式

- 页面顶部显示管理工具栏，包含“上传作品”“保存更改”“取消更改”和未保存状态提示。
- 三个区域分别显示自己的上传入口，也可从统一上传入口选择目标区域。
- 每张作品卡片显示删除按钮和排序控件。
- 桌面端通过卡片拖拽实时改变顺序；移动端通过上移、下移按钮改变顺序。
- 删除前要求二次确认。确认后卡片从当前视图移除，并提供撤销入口，直至保存成功。
- 点击“取消更改”恢复进入管理模式前的作品列表与顺序。
- 页面存在未保存更改时，退出管理模式或关闭页面会收到提醒。

### 上传流程

1. 选择一个或多个媒体文件。
2. 校验格式和大小；不符合要求的文件不会进入列表，并显示明确原因。
3. 为每个文件选择所属区域，默认使用触发上传入口所在的区域。
4. 可选填写中文标题和英文标题。
5. 创建本地预览 URL，立即将作品卡片插入目标区域末尾。
6. 用户可继续拖拽排序、删除或撤销，最终统一保存。

## 数据模型

作品列表从 HTML 静态标记迁移到 `data/graphic-works.json`，页面加载后根据清单渲染三个区域。

每条作品记录包含：

```json
{
  "id": "graphic-20260909-example",
  "section": "graphic",
  "mediaType": "image",
  "src": "../works/graphic/example.webp",
  "title": {
    "zh": "",
    "en": ""
  },
  "order": 10
}
```

字段约束：

- `id`：永久唯一标识，不使用数组位置作为身份。
- `section`：`graphic`、`ai-store` 或 `3d`。
- `mediaType`：`image` 或 `video`。
- `src`：相对于 `pages/graphic.html` 的媒体地址。
- `title.zh`、`title.en`：可为空字符串。
- `order`：区域内显示顺序，保存时归一化为连续整数。

现有的双视频组合卡片作为独立兼容项迁移，保留当前组合展示，不要求第一版上传流程创建新的组合卡片。

## 组件边界

### 作品数据仓库

负责加载原始作品清单、创建编辑草稿、执行添加/删除/移动操作以及恢复原始状态。页面渲染层不直接修改原始数据。

### 作品渲染器

根据作品类型与所属区域生成当前瀑布流卡片或 3D 网格卡片，并在重新渲染后恢复灯箱、视频和现有交互绑定。

### 管理控制器

负责进入和退出管理模式、工具栏状态、未保存提示、删除确认、撤销以及保存状态。它通过作品数据仓库修改草稿，不直接操作持久化层。

### 上传处理器

负责文件选择、格式与大小校验、预览 URL 生命周期、元数据输入和目标区域选择。在线阶段再将合格文件交给保存客户端上传。

### 保存客户端

第一阶段使用本地适配器模拟保存结果并保留调试用导出能力。第二阶段替换为云函数适配器，页面其他模块不需要了解 GitHub API 细节。

### 身份验证层

仅用于在线阶段。负责发起 GitHub 登录、维护短期会话、显示登录状态和处理会话过期。它只决定是否显示管理界面，最终写权限仍必须由云函数再次验证。

## 本地阶段数据流

1. 页面加载 `data/graphic-works.json` 并渲染作品。
2. 进入管理模式时复制一份编辑草稿。
3. 上传文件仅创建浏览器本地预览，不写入磁盘。
4. 删除和排序只更新草稿，页面立即重新渲染。
5. 取消操作时丢弃草稿并恢复原始清单。
6. 本地保存用于验证完整交互，可导出作品清单和待上传文件摘要，不声称修改了项目文件。

## 在线阶段架构与数据流

GitHub Pages 继续承载公开页面；一个独立的云函数承担必须保密的身份验证和仓库写入操作。

1. 用户点击“管理作品”，前端发起 GitHub 授权。
2. GitHub 将授权结果交给云函数，云函数验证防伪状态并换取短期访问凭证。
3. 云函数查询当前 GitHub 用户，并校验用户名是否与配置的唯一管理员一致。
4. 验证通过后建立安全会话；其他账号收到 403，无法创建管理会话。
5. 保存时，前端提交当前清单、待上传文件及原始清单版本标识。
6. 云函数再次验证会话、管理员身份、文件类型、文件大小和路径。
7. 云函数检查仓库版本。如果线上清单已经变化，则返回冲突，不覆盖新版本。
8. 云函数将新增媒体与更新后的 `data/graphic-works.json` 写入同一次仓库变更。
9. GitHub Pages 根据仓库变更重新发布站点。

云函数可部署到 Cloudflare Worker 或腾讯云函数。具体平台在在线阶段实施计划开始前确定，不影响本地编辑器的组件接口。

## 安全设计

- GitHub Token、GitHub App 私钥、客户端密钥不得进入仓库或浏览器代码。
- 云函数使用环境变量或平台密钥存储保存敏感配置。
- GitHub App 仅安装到目标仓库，仅授予内容读取和写入所需的最小权限。
- 前端隐藏管理控件只改善体验，不作为权限边界；每次写请求都由云函数验证。
- 只允许配置的 GitHub 用户名执行写操作。
- 授权请求使用随机 `state` 防止登录请求伪造；会话 Cookie 使用 Secure、HttpOnly 和 SameSite 属性。
- 上传文件采用允许列表校验扩展名与 MIME 类型，并对单文件大小、单次文件数和总请求大小设限。
- 服务端生成安全文件名并限制写入目录，拒绝路径穿越和覆盖非作品文件。
- 保存接口进行速率限制，并记录失败与成功事件，不在日志中记录访问令牌。
- 管理者 GitHub 账号应启用双重验证。

## 删除与恢复策略

第一版删除只修改作品清单，不从 GitHub 仓库物理删除媒体文件。这样可通过 Git 历史或重新加入清单快速恢复误删作品。

后续如需要控制仓库体积，可增加单独的“清理未使用媒体”流程。该流程必须列出精确文件、再次确认并通过独立提交执行，不与普通作品保存混在一起。

## 冲突与错误处理

- 不支持的格式或超限文件在客户端预检阶段拒绝。
- 图片或视频加载失败时显示占位卡片，不阻断其他作品渲染。
- GitHub 登录或会话过期时保留当前草稿，并提示重新登录。
- 保存失败时保留全部编辑状态，允许重试或导出草稿。
- 保存按钮在提交期间禁用，避免重复请求。
- 服务端使用清单版本标识进行乐观并发控制；检测到版本冲突时停止写入并提示用户重新加载。
- 部分上传失败时不更新清单，保证媒体文件与清单不会形成半完成状态。
- 网络恢复后由用户主动重试，不在后台无限自动提交。

## 兼容与响应式要求

- 保持现有桌面四列、平板和手机响应式布局。
- 拖拽手柄只在支持精确指针的设备启用。
- 触摸设备提供明确的上移、下移按钮。
- 管理控件必须可用键盘聚焦，并提供可读标签。
- 动画尊重 `prefers-reduced-motion`。
- 管理改造不得破坏现有中英文切换、主题模式、灯箱、音量面板及视频播放。

## 测试与验收

### 本地阶段

- 三个区域均可添加图片和视频，并在不刷新页面的情况下预览。
- 多文件上传能够逐项显示校验结果。
- 桌面拖拽和移动端上移/下移均产生正确顺序。
- 删除需要确认，保存前可以撤销。
- 取消全部修改后恢复原始作品、标题和顺序。
- 中英文标题可留空，语言切换时不出现空占位。
- 浏览模式不出现编辑控件。
- 页面有未保存修改时，离开页面会提示。
- 灯箱、视频、音效、主题与语言切换继续正常。
- 常见桌面、平板和手机宽度下布局无溢出或遮挡。

### 在线阶段

- 指定 GitHub 账号能够登录并保存。
- 未登录请求、非指定账号和伪造请求均无法写入仓库。
- 令牌和密钥不会出现在页面源码、网络响应或公开日志中。
- 一次保存产生一条内容明确的自动提交记录。
- 保存冲突不会覆盖仓库中更新的作品清单。
- GitHub Pages 发布完成后，普通访客看到与已保存清单一致的内容。

## 分阶段交付

### 第一阶段：本地管理体验

- 建立 JSON 作品清单并迁移现有作品。
- 实现三个区域的数据驱动渲染。
- 实现管理模式、上传预览、删除、撤销、排序、取消和本地保存反馈。
- 完成现有功能回归和响应式检查。

### 第二阶段：在线身份与保存

- 选择并配置云函数平台。
- 创建最小权限 GitHub App 与唯一管理员配置。
- 实现登录回调、安全会话、媒体上传、清单提交和冲突检查。
- 配置 GitHub Pages 发布并完成权限攻击面验证。

## 成功标准

站点所有者可以直接从 Graphic 页面管理三个区域的图片和视频作品，并在上线阶段安全地将修改发布到 GitHub；未授权访客即使看见管理入口、阅读全部前端源码或构造请求，也不能获得仓库写权限。
